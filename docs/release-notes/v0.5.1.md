## TGMT5 0.5.1

A hardening release. Every place where the app could run into an unexpected empty value (`None`) in the execution engine, trade management, the Telegram client and the interface now stops safely with a clear message instead of an `AttributeError` or `TypeError`. The issues were found with a Pyright type check of the application code (146 findings, 29 left, all typing-only and already guarded at runtime). Parsing, sizing, the safety gates and the MONITOR-first start-up are unchanged, and the 299-test suite passes as before.

### Download

| File | Use it when |
|---|---|
| `TGMT5-Setup-0.5.1.exe` | Normal install. Run it over 0.5.0 or 0.4.x: settings, history and passwords are kept, and the database is backed up first. |
| `TGMT5-Portable-0.5.1.exe` | One self-contained file to copy and run, no install. Keeps its data in `TGMT5-data` next to the `.exe`. |

Both are built and smoke-tested on GitHub Actions (Windows, `--sandbox` start-up check). They are signed with a self-signed test certificate, so Windows SmartScreen warns: **More info → Run anyway**.

### Execution & trade management

- **Missing database rows.** If a signal or order row the pipeline expects is gone, the step now stops with a clear `LookupError` (`SignalRow #N not found`) before any order is sent, instead of an `AttributeError` part-way through.
- **MT5 disconnected.** *Close*, *Modify SL/TP* and *Cancel* (manual or from a provider follow-up) now return "MT5 not connected" instead of raising, and position sync waits for the reconnect.
- **Partial close and move SL to break-even.** A missing symbol specification or entry price now fails that leg with a clear reason instead of aborting the whole instruction.
- **Modify SL without a reference price.** Rejected as "new SL implausible" instead of a `TypeError` or division by zero: an SL change that cannot be sanity-checked is never sent.
- **Missing order or position ticket.** *Modify* and *Cancel* no longer send a request without a ticket to the broker.
- **Incomplete signals.** A signal missing its symbol, direction, entry type or stop loss is stopped before sizing.
- **Broker symbol suffix.** Connecting to MT5 now fails loudly if the symbol resolver is missing, instead of silently skipping the configured symbol suffix.

### Telegram

- Using the Telegram client before it is connected, or signing in before a login code was requested, now raises `LoginRequired` with a clear message.
- Disconnecting awaits Telethon only when it returns a coroutine.

### Interface

- *Sources*: empty table cells no longer break *Add selected* or *Save sources*.
- Clearing the *Signals* list and refreshing the current page are guarded against empty widgets.
- The GUI event bridge signal is renamed to `app_event`, so it no longer shadows Qt's `QObject.event()`.

### For developers

- New helper `tgmt5.persistence.db.must_get(session, Model, id)` loads a row the pipeline already knows exists and raises instead of returning `None`.
- `pyrightconfig.json` points Pyright at the `src` layout and the local `.venv`.

### Verification

- 299 tests pass on macOS, and Pyright reports no new findings.
- A `--sandbox` run on macOS processed 16 simulated signals (executed, waiting, manual review) with no errors.
- Not yet verified against a real MT5 terminal on Windows.
