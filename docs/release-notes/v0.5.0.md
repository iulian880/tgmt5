## TGMT5 0.5.0

A comprehensive audit, hardening and documentation release. Twenty-three bugs and edge cases uncovered during a full codebase audit are fixed, backed by 42 new regression tests (`tests/test_regressions_v050.py`, bringing the suite to **299 passing tests** with zero warnings), and the repository has been renamed from `telegram-mt5-copier` to **`tgmt5`**.

### Download

| File | Use it when |
|---|---|
| `TGMT5-Setup-0.5.0.exe` | Normal install. Run it over 0.4.x: settings, history and passwords are kept, and the database is backed up first. |
| `TGMT5-Portable-0.5.0.exe` | One self-contained file to copy and run, no install. Keeps its data in `TGMT5-data` next to the `.exe`. |

Both are built and smoke-tested on GitHub Actions (Windows, `--sandbox` start-up check). They are signed with a self-signed test certificate, so Windows SmartScreen warns: **More info → Run anyway**.

### Trading safety & execution fixes

- **Recovery with unreachable broker.** If MT5 raised a `GatewayError` while reconciling an `UNCERTAIN` leg during start-up recovery, recovery previously marked it as resolved and downgraded the signal to `FAILED` — permanently stopping future reconciliation. Unresolved legs now keep the signal `UNCERTAIN` until broker state is verified, and pending orders restore to `PENDING_PLACED`.
- **Late reconciliation status update.** When an `UNCERTAIN` leg was later found `OPEN` or `PENDING` during a periodic tick, the parent signal stayed `UNCERTAIN` until closed. It now transitions to `EXECUTED`, `PENDING_PLACED`, `PARTIAL` or `SIMULATED`.
- **European comma decimals in follow-ups.** Messages such as *"Move SL to 1,0850"* or *"New TP 2650,50"* silently truncated the price at the comma (moving SL to `1.0`). They now route to `MANUAL_REVIEW`, along with zero/negative prices.
- **Conditional management commands.** *"Close 50% if price hits 2670"*, *"Take 50% when it reaches 2680"*, *"Move SL to BE once TP1 hits"* and *"Cancel pending if it drops below 2640"* previously executed immediately. Conditional follow-ups now route to `MANUAL_REVIEW`.
- **Parser zero-price crash & geometry hardening.** Zero stop-loss, zero entry price or zero zone bounds previously triggered `ZeroDivisionError`; TPs inside an entry zone were accepted; double-spaced `BUY  STOP` could be misread as a stop loss. All are now handled cleanly and safely.
- **Active signal edits in MONITOR mode.** With *Apply provider edits of SL* enabled, editing an active signal while in MONITOR mode attempted to send a broker modification. MONITOR mode now strictly blocks any modification and logs an audit event.
- **Emergency stop leg abort & hourly quota isolation.** If leg 0 triggers `LiveAccountBlocked` (engaging emergency stop), remaining legs of the same signal are immediately aborted as `REJECTED` instead of hitting the guard again. PAPER trades and fully rejected signals no longer burn the real `max_trades_per_hour` counter.
- **Manual partial close resilience.** If you manually close part of a position in MT5, `close_leg` and `sync_leg` now sync with the broker's actual remaining volume instead of failing with `INVALID_VOLUME`, and `GatewayError` during uncertain close checks is handled cleanly.
- **Modify TP validation & clearing.** `MODIFY_TP` now validates positive/plausible target prices and stops-level side, handles `leg.sl = None` safely, and setting `0` in the Positions *Modify SL/TP* dialog now actually removes the Take Profit as labelled.

### Adapter, security & reliability fixes

- **MT5 server clock reset & expiration.** `RealMT5Gateway` resets its learned server-time offset on connect/disconnect (preventing stale offsets when switching servers) and converts non-zero pending order `expiration` timestamps to server time.
- **Symbol resolution.** Mixed-case exact broker names (e.g. `Gold`) now resolve cleanly, and 3-letter currency codes (e.g. `GOLDEUR`) can no longer match as a broker suffix of `GOLD`.
- **Worker-thread serialization.** `emergency_stop`, `clear_emergency`, `save_config`, `reset_breaker` and `reset_drawdown_lockout` all execute on the single `mt5` worker thread, eliminating cross-thread races on `RiskState` and SQLite.
- **Reconnect in MONITOR mode.** Auto-reconnecting while in MONITOR mode with an expired pending order no longer hits `ReadOnlyGateway` with `PermissionError`, and refreshes `SymbolResolver`.
- **Defense-in-depth secret redaction & MONITOR invariant.** `Database.load_config()` enforces `MONITOR` mode on load; `Database.log_event()` recursively redacts structured `data` payloads; `StreamHandler` uses `RedactingFormatter` to redact exception tracebacks.
- **Telegram listener restart.** Calling `start()` again (e.g. *Restart listener* in Sources) removes previous event handlers and cancels the prior watchdog task so messages are never duplicated. `logout()` now clears the client handle cleanly.
- **Offline gold sizing preview & risk guards.** Offline Risk preview for `XAUUSD` now uses gold contract specs instead of 5-digit FX defaults; zero `trade_tick_size` / zero SL distance guards prevent division by zero; pending order open-risk falls back to tick value if `order_calc_profit` returns `None`.

### Interface fixes

- Importing a configuration file now immediately reloads the *Risk*, *Sources* and *Connection* forms.
- Typing fine decimals (e.g. `0.33%`) in the Risk % box is no longer snapped to `0.05%` steps by the slider.
- *Connection* now reports the real account's confirmation status accurately while in PAPER mode; *Dashboard* refreshes charts immediately when switching between DEMO and PAPER; raw signal text on *Signals* is now selectable with the mouse.
- *Sandbox* now includes all major FX pairs plus Gold so the *Risk* preview table shows full broker calculations out of the box.
